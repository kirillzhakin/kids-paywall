# Figma: как получить макет

В репозитории лежит **Figma-плагин**, который собирает экран paywall прямо в вашем
файле Figma — с auto-layout, стилями, палитрой и типовой шкалой. Ничего
устанавливать из npm для этого не нужно.

> Почему плагин, а не «нарисовать вручную»? Скриншоты из `design/screenshots`
> сняты с реального кода, а плагин переносит ту же геометрию и токены в Figma,
> поэтому макет и вёрстка совпадают по пикселям. Правки в Figma дальше делаются
> обычным способом.

## Что появится на странице

| Фрейм | Что показывает |
| --- | --- |
| `Paywall / основной экран` | 390 × 844, выбран тариф «Год» |
| `Paywall / загрузка тарифов` | skeleton-карточки тарифов |
| `Paywall / ошибка загрузки` | баннер ошибки + «Повторить» |
| `Paywall / успешная покупка` | экран успеха с чеком |
| `Design tokens` | палитра, типографика, радиусы |

## Запуск (1 минута)

1. Откройте Figma desktop (приложение уже установлено в `/Applications/Figma.app`)
   и войдите в свой аккаунт.
2. Создайте новый Design-файл: **File → New design file**.
   Имя можно любое, например `Чудо-Остров — Paywall`.
3. В меню: **Plugins → Development → Import plugin from manifest…**
4. Выберите файл:

   ```
   design/figma-plugin/manifest.json
   ```

5. Запустите плагин: **Plugins → Development → chudo-ostrov-paywall**.
6. Через пару секунд на странице появятся все фреймы и секция с токенами.
7. Поделитесь файлом: **Share → Anyone with the link → Can view → Copy link**.

> **Повторный запуск безопасен.** Плагин помечает созданные слои через
> `setPluginData` и при следующем запуске сначала удаляет предыдущий результат —
> дублей в файле не будет. В уведомлении будет указано, сколько слоёв заменено.

## Что проверяется автоматически

```bash
pnpm test:figma      # мок Figma Plugin API + модель auto-layout
```

Тест прогоняет плагин **дважды** и проверяет не только наличие слоёв, но и
геометрию, которую посчитает Figma:

| Проверка | Зачем |
| --- | --- |
| фрейм ровно `390 × 844`, режимы `FIXED/FIXED` | при `AUTO` Figma пересчитывает высоту по контенту и фрейм «схлопывается» |
| внутри auto-layout нет absolute-слоёв | такой слой рисуется **поверх** контента и скрывает весь макет |
| фон — две заливки фрейма (`GRADIENT_LINEAR` + `GRADIENT_RADIAL`) | градиент должен быть фоном, а не отдельной плашкой |
| `top-bar ≤ 60 px`, `cta-bar ≤ 180 px`, `status-bar = 44 px` | ловит утечку дефолтных 100 px из `resize()` |
| повторный запуск даёт столько же слоёв | иначе в файле копятся дубли |

Все пять пунктов — не теория: три из них были реальными багами этой версии
плагина, и тест их поймал до того, как макет попал в файл.

## Про шрифт

Плагин загружает `Nunito` (тот же шрифт, что в реализации). Загрузка
**отказоустойчивая**: начертания подбираются с запасными вариантами внутри
семейства (`Black → ExtraBold → Bold`), а если семейство недоступно целиком —
берётся `Inter`, затем `Roboto`. Единственное, что может случиться при
отсутствии шрифта, — другой шрифт в макете; сборка экрана не прерывается.
Фактически применённый шрифт указан в уведомлении плагина.

## Если что-то пошло не так

Плагин пишет диагностику **прямо на канвас** — блок `Диагностика плагина`
(ниже экранов, координата y = 1250). Там видно:

- версию Plugin API и доступность методов (`findAll`, `setPluginData`, список шрифтов);
- сколько экранов собрано из четырёх и сколько создано слоёв;
- список ошибок, если что-то упало.

Дополнительно каждая из четырёх экранов собирается в собственном `try/catch`:
падение одного не мешает остальным. Все ошибки также печатаются в консоль
плагина (`Plugins → Development → Open console`).

## Про Dev Mode MCP

В задаче упоминался доступ через Figma. У Dev Mode MCP-сервера Figma **только
чтение**: он отдаёт контекст существующего фрейма, но не создаёт и не изменяет
слои. Поэтому макет собирается плагином — у него есть право записи в файл.
Если у вас Dev Mode MCP всё же включён, он остаётся полезен для сверки: в
`design/screenshots/metrics.json` лежат точные размеры и шрифты каждого блока.

## Диагностический плагин

Если основной плагин ведёт себя необъяснимо (например, создаёт пустые фреймы),
есть отдельный плагин из пяти изолированных проверок Plugin API. Он импортируется
как самостоятельный плагин, поэтому его код точно свежий:

```
design/figma-plugin/diag/manifest.json
```

Он проверяет по очереди: фрейм во фрейме, фрейм в auto-layout, текст во фрейме,
вложенность `page → frame → column → text` и два текстовых слоя с разными
семействами шрифтов. Результат пишется в текстовый слой `DIAG-report`
(и в консоль плагина). Этот отчёт можно прочитать через Figma REST API:

```bash
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/<fileKey>?depth=6" | grep DIAG
```

## Способ без плагина: импорт SVG

Если Plugin API в вашей сборке Figma ведёт себя непредсказуемо, макет можно
получить вообще без плагина — Figma импортирует SVG через **Import** или
перетаскиванием, а текст внутри SVG остаётся редактируемым.

```bash
pnpm svg        # пересобрать SVG из server/data/offers.ts
```

| Файл | Содержимое |
| --- | --- |
| `design/svg/00-overview.svg` | **все четыре экрана одним листом** (1760 × 950) |
| `design/svg/*.pdf` | те же экраны в PDF — запасной формат, если SVG не устроит |
| `design/svg/01-main.svg` | основной экран, 390 × 844 |
| `design/svg/02-loading.svg` | загрузка тарифов |
| `design/svg/03-error.svg` | ошибка загрузки |
| `design/svg/04-success.svg` | успешная покупка |

Порядок: в Figma перетащите `00-overview.svg` на страницу (или
**File → Place image** / **Import**). Появится один фрейм со всеми экранами;
текст останется текстом, векторные элементы — векторами.

Цены в SVG не дублируются вручную: генератор читает
`YEARLY_PRICE_MINOR` / `MONTHLY_PRICE_MINOR` из `server/data/offers.ts`,
поэтому макет и приложение не могут разойтись.

## Важно про шрифт в SVG

В `font-family` должно стоять **одно имя шрифта**. Так надёжнее: импортёр Figma
не гарантирует разбор списка через запятую, а шрифт, которого нет в аккаунте,
приводит к потере текста.

Первый импорт макета дал **только формы** — 4 `Group` и один `Vector`, без
единого текстового слоя. Точную причину установить не удалось (я тогда не
проверил гипотезу тестом), но после перехода на одно имя шрифта импорт
заработал: в панели слоёв появились `T`-узлы, фрейм 390 × 844.

Проверка `design/svg/tests/font-test.svg` показала, какие варианты принимает
эта сборка Figma:

| Вариант | Результат |
| --- | --- |
| A1 список через запятую | отрисовался |
| A2 `Nunito` | отрисовался |
| A3 `Roboto` | отрисовался |
| A4 `Arial` | **не отрисовался** — шрифта нет в аккаунте |
| A5 `Nunito` bold | отрисовался |
| A6 без `font-family` | отрисовался |
| A7 `Roboto`, ASCII | отрисовался |

Вывод: запятая сама по себе импорт не ломает, а **отсутствующий шрифт ломает**.
Генератор поэтому пишет `Roboto` — он есть в Figma всегда, включая кириллицу.
Переопределить можно переменной:

```bash
SVG_FONT="Nunito" pnpm svg     # если Nunito точно есть в вашем аккаунте
```

Структуру файлов проверяет тест (парсит SVG, требует одно имя шрифта,
обязательные тексты и совпадение цен с `/api/offers`):

```bash
pnpm test:svg
```

Если текст всё равно не появился, проверьте импортёром
`design/svg/tests/font-test.svg` — он содержит 7 вариантов разметки
(список через запятую, одно имя, без `font-family`, ASCII/Cyrillic) и сразу
покажет, какой вариант ваша сборка Figma принимает.
